### 문서와 실제가 어긋나는 부분 (수정하지 않음)

- **cell6의 NUC 표기**: 설정은 `server/nuc2/`에 있고 주소록도 `nuc = "nuc2"`인데, 실제로는 NUC1에서 loopback으로 돌고 있습니다.
- **cell2/3 펌프**: 주소록 주석은 "펌프 없음"이라고 하지만, 이후 커밋에서 런처에 펌프 지원과 시리얼 검증이 들어갔습니다.
- **README 상단 표**: cell1을 "펌프 없음", cell2/3을 "벤치 미실행"으로 적고 있어 같은 README의 2026-09-17 상태 섹션과 다릅니다.
- **로봇팔 `.lua` 경로**: README 상단 표는 "bench-verified", 상태 섹션은 "NOT bench-verified (#31)"입니다.

## 2. cell5에 선풍기 스마트 플러그 추가

### 플러그 확인

- 요청: `plug_2` / `192.168.0.77`
- `192.168.0.77`의 MAC은 `18:69:45:71:02:7c`로, 드라이버 `device_list.md`의 `plug2`(Tapo P110M)와 일치합니다.
- `device_list.md`에는 `plug2`가 옛 주소 `192.168.1.79`로 적혀 있습니다. 서브모듈은 수정하지 않고, cell5 설정에 IP를 직접 적는 방식으로 처리했습니다(램프와 같은 방식, LearnedPatterns #29).

### 결정 사항

| 항목 | 결정 |
|---|---|
| 정지 명령(`/v1/stop`, abort 브로드캐스트) 시 선풍기 | 히터·교반기·램프와 함께 **끈다** |
| `fan/switch`를 작업자 확인(`confirm_first_motion`) 대상에 포함 | **포함하지 않는다** (`fan/`은 hazard prefix가 아님) |

### 동작 방식

- 새 액션 세트 `fan`: `GET /v1/fan/state`, `POST /v1/fan/switch` (`{"enabled": true|false}`)
- 설정의 `[fan]` 테이블은 선택 사항입니다. 없으면 `/v1/fan/*`는 409로 응답하고 나머지 장치는 그대로 동작합니다.
- `diagnose`에 `fan` 블록, `status`에 `fan_on` 필드가 추가됐습니다.
- 선풍기 타깃이 `"all"`이거나 램프 타깃과 같으면 cell이 시작을 거부합니다. `fan/switch`로 IR 램프가 켜지는 일을 막기 위한 장치입니다.
- 정지 시 선풍기는 열원(히터, 램프) 다음에 마지막으로 끕니다. 선풍기를 끄는 데 실패해도 열원은 이미 꺼진 뒤이고, 실패는 "stop incomplete"로 보고됩니다.

## 3. 남은 일

1. **NUC2에 코드 반영**: cell5 서버는 NUC2에서 돌기 때문에, 이 변경이 NUC2 체크아웃에 들어가야 합니다. 커밋 전이라 전달 방법(브랜치 푸시, 파일 복사 등)을 정해야 합니다.
2. **`server/nuc2/cell5.toml`에 `[fan]` 추가**: 실제 설정 파일은 gitignore 대상이라 NUC2에서 직접 넣어야 합니다.
   ```toml
   [fan]
   target = "192.168.0.77"
   ```
3. **벤치 검증** (작업자 입회):
   - `curl -s localhost:17062/v1/diagnose`에서 `fan.ok`가 true인지 확인
   - `curl -s localhost:17062/v1/fan/state`
   - 선풍기를 켰을 때 **선풍기가 돌고 IR 램프는 꺼진 채인지** 눈으로 확인. 램프가 켜지면 두 `target`이 바뀐 것입니다.
   - `/v1/stop` 후 선풍기가 꺼지는지 확인
4. **검증 후 커밋과 PR**: 이슈 #39에 연결.

Z 모터 전원이 없으면 cell5 서버 자체가 뜨지 않습니다(`open()`에서 Z 모터 setup 실패). 선풍기만 먼저 확인하려 해도 Z 모터 전원이 필요합니다.
