## The concurrency actually happened

Two independent signs in `run.jsonl`, neither of which a sequential run
could produce:

- each pair took the **same** 18.7–18.8 s rather than summing, and
- the children finished **out of submission order** — `r1_home_c7` is
  logged before `r1_home_c6`.

The orchestrator locks per *cell* (`engine.py` acquires
`self._locks.acquire(step.cell)`), so two different cells genuinely run
at once; there is no lock to serialise them.

## What this does not establish

It does not measure the arms' reach overlap. Nothing in software can:
each controller reports poses in its own base frame
(`GetRobotInstallAngle` is `[0, 135]` on both — a mounting *angle*, not
a position). Spec §8.4 / GAP-8 still stands, and this run's safety came
from the operator's eye, not from a measurement. The scenario says so in
a box at its top.
