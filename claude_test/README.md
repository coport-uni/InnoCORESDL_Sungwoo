# claude_test/

Scratch area for debug scripts, one-off experiments, and diagnostic code
(CommonClaude §3 Debug File Management). Production-quality tests go in
`tests/`. When adding a file here, add a row below.

| File | Purpose | Learned |
|---|---|---|
| `conftest.py` | Fixtures + `FakeL1`, an httpx `MockTransport` stand-in for all three cell shapes (cell1–3, cell4, Cell 5). Its hotplate warms 5 °C per state read while heating, so `until:` polls converge in a handful of reads. Deliberately test-level, never a deployable mock server (spec §9). | The L1 OpenAPI is shape-agnostic (one router for every shape), so the fake serves the union too — a *narrower* fake would let tests catch wrong-shape actions the real dry run cannot, which is worse than useless. Wrong-shape calls answer 409, like the cells' defensive stubs. The pump answers are stateful (valve `?6` digit, contained volume) with a shape-aware `/v1/diagnose`, so pump scenarios assert real readbacks rather than canned zeros. `FakeL1.pan_g` models what the balance is carrying: a test for a scenario with an operator step sets it *while the run is paused*, which is what the operator physically does at that pause — leaving it empty makes `verify_vial_present` fail, correctly. `HOME_MM` is **not 0** on purpose: on the real bench the 0 mm encoder origin sits on the mechanical stop, and homing there drove the carriage into it until the amp tripped Err16.0 and killed the servo. A fake that homed to 0 would let a scenario asserting `y_mm <= tolerance` pass here and damage hardware on the bench, so the fake parks where the cell parks. |
| `test_orchestrator.py` | Orchestrator acceptance tests: the six validator errors, the demo scenarios end-to-end (linear, weigh, Cell 5 warmup, and the three Cell 5 bench demos — lamp blink, hotplate 30 °C, Z cycles), the cell1 pump-cycle demo (validates, completes with the 1 unrolled + 9 batched = 10 cycles asserted, aborts before `pump/cycle` on an injected aspirate fault), runlog files, the three `on_fail` policies, abort's stop broadcast, `resume --from-step`, the hazard gate (heater/lamp gated, GETs not), the `wait_s` step (holds, params, bad-value rejection, not gated, cut short by abort), the `until:` polled GET (converges, times out, rejects POST), the scenario-declared operator `pause:` (holds without step mode, fires exactly once, reported separately from the motion gate, rejected on a `parallel` child), the wrong-shape 409, a drift guard against the real L1 OpenAPI, the `/v1` HTTP surface, and the dry run's numeric bounds checking. | `resume(from_step=…)` must re-read the step after the pause gate, or the loop runs the stale one; `resume()` has to flip the state itself so a poller never sees a stale `paused`; and the drift guard has to compare request *fields*, not just paths — that is what would have caught the `on`/`enabled` mismatch. The bounds tests must assert that a **valid** body passes, not only that a bad one fails: the first `_check_bounds` used `value.__lt__(limit)`, which returns the truthy `NotImplemented` for int-vs-float, so it flagged every correct integer field. |
| `smoke_cell1_pump_20260729.md` | Bench record of the two hardware runs of `demo_pump_cycle.yaml`: `20260729T103557Z` (commands 1 → 3, 50 µL — 19/19 yet the liquid only oscillated: 180° pair, same fluid state) and `20260729T104717Z` (commands 1 → 2, 100 µL — 19/19 **and** operator-confirmed reservoir→tip transfer, ~1 mL), plus the priming: fresh solution loaded, three consecutive 1 → 2 runs (30 cycles, ~3 mL) and the pump declared primed. Also documents the CH340 link stability after the servo-driver power fix and the current plumbing (reservoir = physical 1, tip = physical 3). | Runlogs under `runs/` are gitignored, so the numbers that prove the bring-up live here. The pair of runs is LearnedPatterns #1 retold: every wire-level assert can pass while the fluid path never changes, so the transfer check stays a human's. |
| `smoke_cell1_pump_emi_20260729.md` | Bench record of the pump link guard under active EMI: with the amp on (CH340 re-enumerating every few seconds under traffic), `demo_pump_cycle` completed 19/19 (run `20260729T114000Z`, 30 cycles × 100 µL, ~250 s) — 65/65 link drops absorbed, 55 re-issues skipped by the settle probes, 2 error-15 busy-waits, 0 unhandled 500s. | The guard buys usability (~3× wall clock under load), not a cure — the conducted-noise fix ladder and the isolator purchase (`docs/RS485_EMI_evidence_20260729.xlsx`) still stand. Re-issuing is safe on the pump ONLY because its commands are absolute and stroke-bounded; the rail's are not, which is why its moves abort instead. |
| `smoke_l1.py` | Operator-supervised M0 smoke test (spec §4.2): drives one cell server's `/v1` endpoints, stops before every hazardous check until the operator types `go`, and prints a Markdown table for `docs/L1_AUDIT.md`. Suites: discovery, balance, linear, pump, gantry, zstage, hotplate, lamp. | Verdicts for the pump must come from the eye, not the `?6` reply (LearnedPatterns #1); the gantry check has to ask whether *both* Z axes moved; heater and lamp checks are gated exactly like motion. |
| `preflight.py` | Bench pre-flight, read-only: enumerates the attached USB/FTDI devices, resolves every address in `server/nuc*/*.toml` against them, resolves *unset* `port` fields against each driver's own auto-detect signature (`AUTO_DETECT`), checks that this user may actually open every port that resolved, flags leftover `TBD-…` placeholders, and checks whether a cell's TCP port is already taken. Never opens a serial handle (`os.access` only stats the node), so it is safe to run while a cell server is up. | Half of a bench day is lost to "which adapter is which"; answering it before `python -m server` is cheap. Built-in `ttyS*` ports have to be filtered out or they drown the real devices. Resolving an address is not the same question as being allowed to open it, and a field left to auto-detection must be resolved against the live bus — reporting either as a pass let a bench that could not start print "Pre-flight clean" (LearnedPatterns #10). |
| `smoke_l1.py` (probes) | `--suite stop` (A4) and `--suite concurrency` (A7) drive a long move in a worker thread and measure a second request against it. | The stop probe found GAP-9 before it ever reached the bench: `/v1/stop` waits on the same lock as the move, so it reports `preempted=False`. A safety probe that only asks the operator "did it stop?" would have missed the *why*. |
| `test_balance_linear_cell.py` | Unit tests for cell4's `BalanceLinearCell.diagnose()`, with the amp and balance injected as fakes (the constructor takes both drivers, so no hardware and no monkeypatching). Covers a silent amp, a silent balance, half an answer from either, and the absent-by-design pump. | `diagnose()` used to hardcode `ok: True` and `ok_to_initialize: true`. On the bench that made it answer "healthy, safe to start" for an amp returning `None` to every read — the same fabricated-success bug LearnedPatterns #15 removed from the motion path, still sitting in the *pre-flight* check meant to catch it. A health check that cannot fail is not a check; derive `ok` from the reads, never assert it. |
| `test_pump_gantry_cell.py` | Unit tests for cell1's `PumpGantryCell`, with the pump and all three motors injected as fakes. Covers the pumpless configuration (every `/v1/pump/*` action 409s, the gantry still moves, `stop`/`close` skip the absent pump), `diagnose()` against a silent motor, and the encoder-readback confirmation on `move`/`home` — including a dropped move, an unreadable axis, and a desynced Z pair. | `MKSMotor.move_to` *prints* `[ERROR] Motor failed to start` and returns rather than raising, and `move_sync` discards its return value — so the cell reported `200 OK` with the requested position for a gantry that never moved, the same fabricated success as cell4's rail but on the axis whose paired-Z desync wrecks the mechanism. A move is only real if the encoder says so. The group helpers are `staticmethod`s on `MKSMotor`, so the fakes only take effect if the test patches the class, not the instances. |
| `test_arm_replay_cell.py` | Unit tests for cell6/cell7's `ArmReplayCell`, with the fairino RPC and the lerobot subprocess runner injected as fakes (the constructor takes both, so no hardware and no conda env). Covers spec §7 T0-1…T0-10 — config parsing of both example TOMLs, the `allowed_repo_prefixes` gate, episode range, the fps rule, the timeout formula, the `lerobot-replay` argv against `6__replay.sh`, replay re-entry, non-zero exit, the two-stage `stop()`, and the start-pose tolerance — plus the SDK session hand-over and the `status()`-during-replay rule. | These do **not** verify the hardware; the bench does (CLAUDE.md rule 4). Two traps they do pin: `reconnect` must be injectable or a unit test dials the real arm at 192.168.0.58 (it did, and hung the suite); and the fake must implement the *probe contract* — an out-of-range episode returns no `frames` — or the range check passes on a fake that always answers fully. Joint reads go through the fake's `.robot` proxy because that is the path the cell really uses (LearnedPatterns #40). |
| `smoke_arm_par30_20260811T040822Z.md` | Bench record of **both arms jogging joint 1 ±30° at the same time**, 2/2 rounds / 8 moves, worst increment error **0.0007°**. Verifies the orchestrator's `parallel:` path across two arm cells and the raised 30° jog cap. | Concurrency is proven from the runlog, not assumed: each pair took the *same* 18.8 s instead of summing, and the children finished out of submission order. It does **not** measure the arms' reach overlap — nothing in software can, since each controller reports poses in its own base frame — so GAP-8 still stands and this run's safety came from the operator's eye. |
| `probe_arm_lua.py` | Phase-0 reconnaissance for the FR5 Lua job-program path, **read-only**: lists the Lua programs actually on a controller, and captures the raw shapes of `GetProgramState()` and `GetLuaList()` off the wire. Issues getters only — no `Mode()`, no `ProgramLoad/Run`, no `MoveJ`. | The vendored SDK's `GetProgramState()` is a stub whose XMLRPC body is commented out; it hard-returns the dead port-20004 struct behind LearnedPatterns #40. So the wire shapes have to be measured before `arm/program` is designed on them, not read off the wrapper. Stop the cell server first — one owner per device, and here that is a TCP session (CLAUDE.md rule #2). |
| `smoke_arm_fr5_a_20260811T033622Z.md` | Bench record of **T1 passing on cell6** (fr5_a, 192.168.0.58), 3/3, worst increment error **0.0010°** (best round 0.00005°). | `smoke_arm_fr5_b_20260811T031924Z.md` | Bench record of the **T1 acceptance test passing on cell7** (fr5_b, 192.168.0.59): joint 1 +10° and back, three rounds, run by the operator through the per-arm scenario that has since been merged into `scenarios/test_arm_jog10.yaml`. | `smoke_arm.py` | **Fallback** T1 path — the primary one is now `scenarios/test_arm_jog10.yaml` over the `arm/jog_joint` route, so the run gets the orchestrator's operator gate and a runlog. Keep this for a bench with no orchestrator, and for the SDK notes below. T1 smoke for one FR5 arm: reads joint 1, MoveJ +10°, re-reads, reads a **second** time independently, checks joints 2–6 held, returns, ×3 rounds; writes `smoke_arm_<robot_id>_<UTC>.md`. Typed `MOVE` confirmation before the first motion, no skip flag (spec §8.2). Deliberately avoids the replay path — it proves the *encoder*, not lerobot. | The pass criterion is the **increment**, not the endpoint (LearnedPatterns #33) — an endpoint check passes on an arm that never moved but happened to start there. The two reads are issued separately and a run of bit-identical pairs is flagged, because agreement to the last digit is evidence of a cache (LearnedPatterns #34); the real arm's reads jitter in the 4th decimal. Both the read and the move use the raw XMLRPC calls, never the SDK wrappers (LearnedPatterns #40, #41). |

| `episode_joint_range.py` | Read-only pre-flight for a **cross-arm replay**: scans a recorded episode's whole action column for its per-joint travel, optionally reads the target controller's `GetJointSoftLimitDeg` over raw XMLRPC, and prints a margin table with a verdict (exit 1 when a joint leaves the limits). Touches no motion and no enable, so it is safe while a cell server holds the arm. Verified 2026-08-11 against cell6: episode 10 of the task3 dataset is within limits, worst margin **+26.46°** on joint 1. | The cell refuses a replay that *starts* more than `MAX_START_APPROACH_DEG` from the first frame, but nothing checks the rest of the trajectory — and `lerobot-replay` streams recorded angles without asking whether this arm can reach them, so the refusal would land mid-motion (LearnedPatterns #43). The pair ordering of the 12 returned limits is not worth trusting to documentation; take `min`/`max` of each pair. A margin of a tenth of a degree is a coincidence, not clearance, so anything under 5° prints `tight` rather than `ok`. |
